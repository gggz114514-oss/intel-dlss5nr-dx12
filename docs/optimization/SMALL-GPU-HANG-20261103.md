# Small GPU 挂死：从错误归因到池布局修复

日期：2026-11-03。平台：Intel Arc B580，驱动 32.0.101.9150，Windows。对象：Small 76 rows / 222 buffers / 108 dispatches / 2 history edges。

## 最终处理

对 Vulkan 池中 `4096 < allocated <= 65536` 的缓冲区，将绑定偏移对齐要求提高到至少 4096 字节，保留原来的 Vulkan memory requirement。分配新 slot 和复用旧 slot 必须使用相同对齐要求。模型、权重、SPIR-V、派发数、计算顺序均不变。

实现位于 [pool_buffers()](../../source/vulkan/port_network_bridge_backend.cpp)。这是经复现与对照选出的地址布局规避，不是添加超时重试或提高 Windows TDR。

| 成本 | 结果 |
|---|---|
| 组件池分配 | 524,967,744 → 525,099,072 B，增加 131,328 B（0.025%） |
| 分配对象 | 仍为 2 个 |
| 额外每帧 dispatch / barrier / CPU 回读 | 0 |
| 有效短窗口配对网络耗时 | 约 +0.014 ms（+0.13%） |
| 64 帧、真实输入、同反馈的父／候选输出 | 逐字节相同 |

修复版 Small DLL：`1d9809991a4f2293dbdeb5239ee4078e7831ff8b774539b0c2dddc059a534632`。发布包内的 `nr-intel/small/nrvk_bridge.dll` 保留此身份。

## 1. 最初看到的不是普通掉帧

死亡搁浅和巫师三出现瞬间卡顿、数秒至数十秒停顿，最终 NR 暂停或设备丢失。一次问题发生在改结构强度时，一次发生在切焦点时；随后未进行这些操作也复现，因此滑块和焦点不是已证明的必要触发动作。

组件表现为：输入拷贝／side 工作完成，网络完成值停止推进。纯 Vulkan 回放返回 `VK_ERROR_DEVICE_LOST (-4)`。12 次离线丢设备都伴随约 4.3–5.0 秒后的 Windows LiveKernelEvent `0x141`，其中 11 条故障桶为 `LKD_0x141_Tdr:6_IMAGE_igdkmdnd64.sys_BMG_VULKANCOMPUTE_BBHANG`；游戏故障也出现同类桶。

这说明 GPU 提交停止推进并触发 TDR；故障桶本身不等于已经证明驱动缺陷，也不能排除地址访问与资源合同问题。

## 2. 怎样把问题缩到纯网络

每次只改变一个条件，并保存第一次失败：

| 对照 | 观察 | 可得结论 |
|---|---|---|
| 关闭 feedback／history | 仍挂 | 帧间历史更新不是必要条件 |
| 冻结历史源、固定输入与种子 | 输出帧间逐位相同后仍挂 | 不需要输入数值随帧改变 |
| 历史复制独立 submit 并等待真实完成 | 仍挂 | 这条复制分界未消除故障 |
| 禁用别名复用 | 仍挂 | 不是简单的声明级寿命重叠解释 |
| 关闭时间戳 | 仍挂 | 时间戳不是必要条件 |
| 纯 Vulkan，无游戏／D3D12 导入信号量 | 仍挂 | 游戏桥不是该复现路径的必要组成 |
| 全输出 NaN／Inf 扫描 | 无非有限值 | 不能用数值爆炸解释当次固定输入复现 |

不要把这些写成“host 所有可能问题已排除”。它们排除的是具体受测解释；后续仍须看真实分配、描述符和访问范围。

## 3. Full 对照比逐 pass 盲拆有效

同协议零输入、独立进程，Full 两轮各 29,000 帧／约 514 秒 GPU 时间完成；Small 对应轮在 37.7 秒和 5.3 秒挂死。Full 只跑前 108 entry（与 Small 深度相当）也完成约 424 秒。

39 个 SPV 中 34 个逐字节相同，5 个是 Small 专用核。对 4 个可疑 Small 派发将 `push[2]` 从 `0xffffffff` 改为 Full 的 0，仍约 140 秒挂死。其余几何差异仍按真实模型保留。

这里能否定“只是每帧派发数少”和这一个 PUSH 字的解释；不能据此证明所有 Small 专用核无缺陷。早期 `--passes K` 混淆文件序号与重复 row，相关逐 pass 定位结论撤回。后续全部用 plan ordinal 加完整身份定位。

## 4. 真正有效的分离：分配布局与 clear

Small 改为逐 buffer 独立分配后，51,000 帧、约 505 秒 GPU 时间完成。但该分支同时改变 per-pass clear，因此再做两臂：

- **flat + 相同 clear**：约 517 秒完成。
- **pool + 不 clear**：约 254 秒仍挂。

因此 clear 不是消除故障的原因，分配布局成为有依据的主线。仅仅看到某一臂“没挂”就直接宣称修复是不够的，必须拆开随实现一起变化的条件。

## 5. 布局实验与最小成本方案

| 布局 | 已记录窗口 |
|---|---|
| 按 Vulkan requirement 紧密排列（本机常见 64 B） | 多次挂死，约 5–254 秒 |
| 全部 4 KiB 对齐 | 51,000 帧／约 510 秒完成 |
| 只对 ≤4 KiB 的 16 个缓冲对齐 | 453 帧挂死 |
| 只对 (4 KiB, 64 KiB] 的 24 个缓冲对齐 | 51,000 帧／约 510 秒完成 |
| 分块池 | 完成受测窗口，额外显存约 7.7% |
| 逐缓冲独立分配 | 完成受测窗口，额外显存约 67.6% |

选择窄对齐方案：主要涉及权重／辅助 pack，24 个缓冲合计 810,176 B。它保留池化和合法别名复用，只移动少量绑定偏移。

**重要纠正：早期“同一个 4 KiB 页里挤了多个缓冲，所以页共享是必要条件”的结论撤回。** 后续页覆盖核查发现，通过布局仍有 22,499 个被多个 buffer 共享的页，24 个对齐缓冲中 9 个仍与后续缓冲共享尾页。已证明的是特定布局规则在测试中消除了复现；没有证明页共享本身是根因。页级跟踪／TLB／特定地址访问只能列为竞争解释。

## 6. 速度不是完全零代价

短窗口 6 对 × 每臂 2,000 帧，交替先后，使用网络 GPU 时间戳。4 对完成，2 对父臂发生 TDR（约 1,458／1,520 帧）而无效，保留失败记录，不把它们补跑成成功样本。

有效配对平均增量 +0.0136 ms，95% CI [+0.0125, +0.0147] ms；中位差约 +0.0140 ms，约 0.13%。这是完成窗口内的条件比较，不代表失败帧的延迟也如此。[配对原始汇总](../releases/small-pool-perf-pairs.json)。

因此不能继续用早期不同批次 10.0–10.2 ms 的粗测量说“零成本”。运行指令不变，也不代表地址布局绝不影响性能。

## 7. 数值、真实输入与超频复测

- 64 帧真实输入＋连续反馈：父／候选输出逐字节一致，SHA256 `cd7d8d37b9786fd6addc8cedfc19d33fce02f2b1190fa9e175d24431f5bc6a86`。
- 真实采集输入＋固定种子＋连续历史反馈：70,000 帧窗口通过，无新 TDR。
- 用户手动超频后再次用同类真实输入跑 70,000 帧，744.5 秒墙钟，GPU mean **9.931 ms/帧**，exit=0、正常关闭、无超时／DEVICE_LOST／新 0x141。输出 7,372,800 个 float，NaN=0、Inf=0。
- 该真实输入 runner 使用相同分配谓词，**不加载候选 DLL**；加载候选 DLL 的组件长跑使用合成输入。两种证据分开记录。
- 超频 70k 末帧与此前默频末帧不逐位相同，相关系数 0.99999994、最大差约 1.08e-3。没有做隔离运行前，不把它归因为超频，也不把它当新数学错误。
- 超频状态由用户报告；未取得频率、温度、功耗遥测，利用率采样不替代时钟验证。
- 早期三次组件长跑没有持锁凭据，不用于补足合规证据。后续真实输入压力测试记录了独占锁取得、互斥检查和释放。

通过表示指定输入、驱动和暴露窗口内完成；真实游戏仍按版本身份记录实测，不把离线窗口写成永久保证。

## 8. 可复用的方法

1. 保存第一次故障：CPU 错误、GPU fence／timeline、Windows TDR、精确包身份必须能对应。
2. 先做纯 Vulkan 复现，把游戏同步与网络执行分开。
3. 用稳定的同族 Full 作为对照，核实实际 SPV／PUSH／grid／分配差异。
4. 发现成功臂，立即拆分其夹带变化：本次关键就是 flat 与 clear。
5. 缩到最小布局规则，同时检查新建 slot 和复用 slot；不能只修一侧。
6. 不把“地址变了”直接解释成已知硬件机制；尾页覆盖核查会推翻看似合理的故事。
7. 数值门、稳定性窗口和速度配对各自记账。没有收益不等于方向错；没有再现不等于根因已证明。
8. 不用提高 TDR、自动重试、强制全局等待或降频充当软件修复。

## 9. 回退与复现资产

用户通过安装包卸载器恢复安装前文件，保留 `intel-nr-install.json` 和备份目录。开发者对比源实现时，只切换 slot 对齐策略，保持 shader／权重／计划和输入不变。

公开包身份见 [20261103 manifest](../releases/20261103-package-manifest.json)，完整采集帧和 GPU dump 不进入源码仓库；经验笔记、数值身份及配对统计足以追溯本次结论，重新采集按实验工具流程执行。
